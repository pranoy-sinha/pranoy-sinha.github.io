CareJourney Multi-Environment Deployment

Getting a Next.js frontend and FastAPI backend running cleanly across Dev, QA, and Production on a shared VPS — untangling JWT secrets, Nginx routing conflicts, cookie stripping, and Node.js version hell.

RoleDevOps & Backend Engineer
PlatformHostinger VPS · Nginx · PM2
DomainHealthcare SaaS
TypeMulti-Env Deployment & DevOps

The Problem

Three environments, one VPS, and nothing talking to each other correctly

CareJourney is a healthcare web application with a Next.js 14 frontend (App Router with server-side rendering) and a FastAPI backend. The client needed Dev, QA, and Production environments running simultaneously on a single Hostinger VPS, with isolated data, separate ports, and independent CI/CD pipelines.

The initial deployment attempt had authentication completely broken: users could log in but were immediately redirected back to the login page on every page load. Background API calls returned 401s despite valid credentials being issued.

The actual root cause was three independent bugs compounding each other: mismatched JWT secrets between Next.js Auth and FastAPI, Nginx stripping Set-Cookie headers on proxied responses, and Node.js v22 (installed via nvm) conflicting with the system Node.js v18 used by PM2.

Diagnosis & Fixes

Peeling the onion — three bugs masking each other

1
Node.js version conflict — PM2 running wrong binaryPM2 was installed globally under system Node v18, but the Next.js app required v22 features. The fix: install PM2 inside the nvm-managed v22 environment and update the PM2 ecosystem.config.js to explicitly reference the nvm binary path. Added node_args and interpreter fields to lock the runtime.
2
JWT secret mismatch between Next-Auth and FastAPINext-Auth was signing JWTs with a NEXTAUTH_SECRET set in .env.local. FastAPI was reading a different JWT_SECRET from its .env file — both valid secrets, but different. Fixed by unifying to a single shared secret injected via GitHub Actions secrets, and updating both .env files from the CI pipeline on deploy.
3
Nginx stripping Set-Cookie on proxied auth responsesNext-Auth issues a session cookie via a Set-Cookie header on the /api/auth/callback route. Nginx's proxy_pass was rewriting the response and dropping cookies marked with domain attributes that didn't match the VPS hostname. Fixed with proxy_cookie_domain and proxy_cookie_path directives, plus ensuring the cookie's SameSite=Lax attribute was preserved.
4
Routing conflict — /api/auth hijacked by Nginx before Next.js handled itNginx was forwarding ALL /api/* requests to FastAPI on port 8000. But /api/auth/* belongs to Next-Auth and must be handled by the Next.js process on port 3000. Fixed by adding a specific location block for /api/auth/ that proxies to the Next.js port, placed before the generic /api/ block.
# Nginx config — routing fix (simplified) server { server_name app.carejourney.com; # Next-Auth routes — handled by Next.js location /api/auth/ { proxy_pass http://localhost:3000; proxy_cookie_domain localhost app.carejourney.com; } # All other /api/* — FastAPI backend location /api/ { proxy_pass http://localhost:8000; } # Everything else — Next.js frontend location / { proxy_pass http://localhost:3000; } }
