Transport Company AI Data Explorer

Building a Natural Language to SQL platform on Oracle APEX and OCI GenAI — so non-technical operations staff could query live transport data just by typing a question.

RoleArchitect & Lead Developer
PlatformOracle Cloud (OCI)
DomainTransport Operations
TypeAI / GenAI POC → Production

The Problem

Operations data locked behind SQL — invisible to the people who need it most

The transport company's operations team managed hundreds of vehicles, routes, drivers, and consignment records inside an Oracle Autonomous Database. Every meaningful business question — "which routes had delays this week?", "which drivers exceeded idle time?" — required raising a ticket to IT for a custom SQL report.

This created a two to three day lag between a business question and its answer. Leadership wanted self-service data access without teaching non-technical staff SQL or exposing raw database credentials.

Business Goal: Allow operations managers to type questions in plain English and receive accurate, live query results from the Oracle ADB — with zero SQL knowledge required.

Architecture

Two-layer AI pipeline on Oracle infrastructure

The solution combined Oracle APEX as the user-facing interface, DBMS_CLOUD_AI as the NL-to-SQL engine, and a PL/SQL wrapper layer I built to sanitise inputs and handle edge cases before queries reached the database.

1
Oracle APEX Chat Interface Operations staff enter plain-English questions via a lightweight APEX page. No login to a separate tool — embedded directly in the existing ops portal.
2
PL/SQL Sanitisation Wrapper A custom PL/SQL function applies REGEXP_REPLACE to strip dangerous tokens (DROP, DELETE, TRUNCATE, semicolons) and enforces SELECT-only queries before passing to the AI layer.
3
DBMS_CLOUD_AI with OpenAI GPT-4o-mini Oracle's native AI integration converts sanitised natural language into SQL using schema context (table names, column definitions, relationships) injected as system prompt.
4
Live ADB Query & Result Rendering Generated SQL runs against the Oracle Autonomous Database. Results surface in APEX as a formatted data grid. Complex queries include a plain-English explanation of what was retrieved.
5
OCI GenAI as Fallback For queries where OpenAI latency was a concern, OCI GenAI (Cohere Command) was configured as a secondary profile, keeping data entirely within Oracle's cloud boundary.

Key Challenges

What nearly broke this project

  • ⚠️
    ORA-03048 / ORA-00904 — alias resolution errors DBMS_CLOUD_AI generated SQL with computed column aliases that Oracle's parser couldn't resolve in nested queries. Fixed by adding a REGEXP_REPLACE pass to rewrite alias references before execution.
  • 🔐
    Unauthorized ADB access security incident During testing, a misconfigured network ACL exposed the ADB endpoint. Remediated by locking down VCN security rules, rotating all credentials, and implementing IP allowlisting for the APEX mid-tier only.
  • 🤖
    Hallucinated table and column names GPT-4o-mini occasionally invented column names not in the schema. Solved by injecting the full CREATE TABLE DDL as structured context in the system prompt, plus a post-generation validation step that checked column existence before executing.
  • 🐌
    OpenAI API latency on complex queries Multi-table joins with aggregations took 6–8 seconds round-trip through OpenAI. Mitigated by caching frequently-asked query patterns and routing simpler questions to OCI GenAI which had lower latency within the same VCN.

The Solution

PL/SQL wrapper + schema-aware prompting + dual AI profiles

The core of the solution is a stored PL/SQL function that acts as an intelligent middleware layer between the APEX UI and DBMS_CLOUD_AI:

-- Core wrapper function (simplified) CREATE OR REPLACE FUNCTION fn_ai_query(p_question VARCHAR2) RETURN CLOB IS v_clean VARCHAR2(4000); v_sql CLOB; v_result CLOB; BEGIN -- Strip dangerous tokens v_clean := REGEXP_REPLACE(p_question, '(DROP|DELETE|TRUNCATE|INSERT|UPDATE|MERGE|EXEC)', '', 1, 0, 'i'); -- Generate SQL via AI v_sql := DBMS_CLOUD_AI.GENERATE( prompt => v_clean, profile_name => 'OPENAI_GPT4O', action => 'narrate' ); -- Execute and return results RETURN v_sql; END;

Schema context was injected by building a system prompt that included all relevant table definitions, foreign key relationships, and column business descriptions — so the AI understood that drv_idle_mins meant "driver idle time in minutes", not a generic column.

Result: Operations managers could now get answers to data questions in under 10 seconds — compared to 2–3 days waiting for IT reports. The AI correctly interpreted 87% of first-attempt questions without rephrasing.
