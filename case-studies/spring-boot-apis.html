HealthApi & simpleShop REST APIs

Two production-grade Spring Boot 3.x APIs demonstrating enterprise patterns: JWT auth, generic response wrappers, global exception handling, and Jackson serialisation control — the kind of code that survives a code review.

The Goal

Reference implementations of enterprise Spring Boot patterns

HealthApi is a healthcare records API (patients, appointments, physicians, prescriptions) built to demonstrate full CRUD, JWT-secured endpoints, paginated list responses, file upload/delete, and a global exception handler that returns consistent error shapes regardless of where the exception occurs.

simpleShop extends these patterns into an e-commerce context (products, orders, customers, inventory) with a focus on a generic ReturnSet<T> response wrapper that works across any entity type — and Jackson configuration that suppresses null fields cleanly.

Key Patterns

The engineering decisions that matter

1
Generic ReturnSet<T> response wrapperEvery endpoint returns ReturnSet<T> — a typed wrapper with status, message, data (the payload), and pagination metadata. This gives API consumers a consistent contract regardless of which entity they're working with.
2
Spring Security 6 + JWT — stateless authJWT filter chain validates tokens on every request. No session state. Refresh token rotation with a 15-minute access token and 7-day refresh token. Role-based access control via @PreAuthorize annotations on controller methods.
3
GlobalExceptionHandler with @ControllerAdviceCatches ValidationException, EntityNotFoundException, AccessDeniedException, and generic RuntimeException — returning structured error responses with HTTP status, error code, and human-readable message. No stack traces leak to the client.
4
@JsonInclude(NON_NULL) on all DTOsJackson configured to suppress null fields globally. No more empty "address": null fields polluting API responses. Optional fields simply absent from the JSON when not populated.
5
Lombok + JPA — clean entity definitions@Data, @Builder, @NoArgsConstructor on all entities. JPA relationships mapped with fetch strategies tuned to avoid N+1 queries. @EntityGraph used on complex joins instead of LAZY fetch with explicit join fetch in JPQL.
// Generic response wrapper @Data @Builder @JsonInclude(JsonInclude.Include.NON_NULL) public class ReturnSet<T> { private String status; private String message; private T data; private Integer totalRecords; private Integer page; private Integer pageSize; }
